## Блок кода
```csharp
string GetHint(int difference) {
    switch (difference) {
        case <= 3:
            return "Горячо!";
        case <= 10:
            return "Тепло.";
        case <= 25:
            return "Прохладно.";
        default:
            return "Холодно!";
    }
}
```

## Главные выводы
1. `if/else` — универсальный инструмент, подходит для любых условий.
2. `switch/case` удобнее, когда одна переменная сравнивается с конкретными значениями, `break` обязателен.
3. Тернарный оператор `? :` хорош для простых случаев «одно из двух». Если условий больше, то лучше `if/else`.

## Ответы на вопросы

**1. Чем `int.TryParse()` безопаснее `int.Parse()`? В каких случаях стоит использовать каждый?**
`int.Parse()` показывает ошибку, если строку не удалось превратить в число. `int.TryParse()` не показывает, а просто возвращает `false`, если преобразовать не удалось. `int.Parse()` можно использовать, когда ты на полностью уверен, что там число. `int.TryParse()` - когда данные приходят от пользователя, и он может ошибиться.

**2. Когда `switch` удобнее, чем цепочка `if/else if`? Приведите пример из реальной жизни.**
`switch` удобнее, когда одна переменная сравнивается с несколькими конкретными значениями. Пример из жизни: в игре «Угадай число» мы использовали `switch` в функции GetHint. В зависимости от того, насколько близко игрок подошёл к загаданному числу, программа выдаёт разную подсказку. Если разница маленькая - пишет «Горячо». Если чуть больше - «Тепло». И т.д.

**3. Что произойдёт в `switch`, если убрать `break` после одного из `case`?**
Выполнение уйдет в следующий `case`. Программа выполнит код текущего `case`, а затем без остановки перейдёт к следующему `case` и тоже его выполнит. Это может привести к неверным результатам.

**4. Чем отличается `=` от `==` в C#? Почему это частая ошибка?**
`=` - это записать значение в переменную. `==` - это проверка, равны ли два значения. Частая ошибка потому, что в математике знак `=` означает равно, а в программировании - присвоить.

**5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.**

Это делает код более читаемым.
